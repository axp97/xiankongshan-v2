# 生产可信度第二轮评审（2026-11-16）

> 性质：只读代码评审 + 本地命令复验；不是专业心理/医疗评审，不是云端或真机验收。
>
> 任务状态唯一事实源仍为 `harness/plan.md`，跨会话入口仍为 `harness/memory.md`。本报告只保存证据与验收口径，不另建待办体系。

## 1. 结论

当前项目不是纯静态 Demo：已有 Taro 分层、真实云函数、DeepSeek 接入、风险状态、反依赖逻辑和生产 UI。

但原有“代码侧生产 MVP 已就绪，剩余仅人工步骤”的结论被本轮评审**取代**。当前准确定位是：

**具备真实工程骨架的体验版候选；仓库内仍有确定性 P0 缺陷，尚未达到可信内测，更未达到公开生产。**

推进顺序固定为：请求与安全状态正确性 → 云端契约与内容安全 → 反依赖正确性 → 真机闭环 → 公开生产治理 → 产品增强。

## 2. 本次实际验证

在干净工作区安装锁定依赖后执行：

- `npm run verify`：通过；typecheck、lint、4 个测试文件共 23 个测试、weapp 构建均全绿。
- `npm run build:h5`：通过；入口 305 KiB，超过 webpack 推荐的 244 KiB，有体积警告。
- `npm audit --omit=dev --registry=https://registry.npmjs.org`：报告 23 项（8 moderate / 9 high / 6 critical）。这些主要来自 Taro 传递依赖，**不能直接等同于 23 个线上可达漏洞**，需按可达性升级分诊；根审计不覆盖两个云函数的独立依赖图。
- 安装时当前 Node `22.12.0` 不满足传递依赖 `eslint-visitor-keys@5.0.1` 声明的 `^22.13.0` 等范围，工具链需升级并固定。

未执行：真实 DeepSeek 调用、真实 `msgSecCheck`、云控制台配置核验、体验版分发、iOS/Android 真机主路径与安全路径。仓库 2026-08-08 的最新真机记录仍为 `callFunction` 失败；云侧当前实况须在 D1/D2 重新确认，不能由本地构建推断。

## 3. 对首轮评审的校正

1. 输入和输出都存在 `msgSecCheck` 调用点；问题是 fail-open、2500 单元截断和缺少医疗语义校验，不是“输出完全未审”。
2. `getAnonymousId` 没有固定 250ms 等待。真实问题是异步 login 未完成时可发送 `undefined`，且 `aiGateway` 当前不消费该 ID。
3. 已有 DeepSeek socket 25s 与云函数 60s 配置；缺的是严格端到端 deadline、response 生命周期和客户端取消/失效管理。
4. 依赖审计数量不等于线上可利用数量，也不代表云函数供应链已审。

## 4. P0 确定性缺陷（可信体验版前）

### R1 · 会话请求代次、响应归属与清除边界

证据：`src/features/chat/useChat.ts:74-88,105-146,170-175`，`src/features/chat/messages.ts:2-10`。

- 多个请求按完成顺序修改同一风险状态。普通 A 慢、高危 B 快时，旧 A 后返回可把新 B 的 high 降为 transition。
- 所有错误/慢重试共享 `lastUserText`；点击 A 的错误可能重发 B，且会删除全部错误条。
- 慢重试不使原请求失效，可双发、双回并放大成本。
- `clearSession` 不使在途请求/followup/timer 失效，旧回复、错误或 high 可在清除后复活并污染新会话。
- 清除未完整处理 `lastUserText`、composer 草稿和全部会话元状态。

验收：旧响应不得改变新请求风险态；每个错误只重试自己的原文；同一逻辑请求只产生一组有效结果；清除后任何旧任务不得写回。

### R2 · 提供方错误与运行时必须契约

证据：`cloudfunctions/aiGateway/index.js:60-88,108-130`，`src/infra/ai/cloudGateway.ts:10-20`。

- 未检查 HTTP `statusCode`；401/429/500 等合法 JSON 错误体可变成 `OUTPUT_FALLBACK + none`，被 UI 当成正常陪伴回复。
- 云端非 JSON、未知 riskLevel 和客户端未知 riskLevel 均向 `none` 降级，混淆“无法识别”与“确认正常”。
- 在既有 high 后，伪正常结果可触发 transition，解除风险状态。
- response `error/aborted`、响应体大小和严格总 deadline 未闭环；完整生产加固列入 F1，但错误不得伪装成功属于 R2。

验收：401/403/429/5xx、空 choices、非法 JSON、非法枚举、错误字段类型均进入明确错误/安全降级，不得显示为正常回复，不得解除既有 high。

### R3 · 输入边界与内容安全三态

证据：`cloudfunctions/aiGateway/index.js:24-43,90-108,125-127`，两个 composer 均为 `maxlength={-1}`。

- 只检测前 2500 个 UTF-16 单元，完整输入仍外发、完整输出仍可能展示，未检后缀形成确定覆盖缺口。
- 无 OPENID、调用异常会放行；空响应/缺 `result` 还会静默放行。
- 文档已披露内测 fail-open，但公开生产必须重新裁决。建议统一为 `pass / blocked / unavailable`，生产输入不可用不调用模型，输出不可用使用审定兜底；无 OPENID 例外只限隔离测试环境。
- 云函数必须实施权威长度上限，不能只靠客户端。

验收：超限输入不调用 DeepSeek；null/缺 result/无 OPENID/限流/网络异常均走明确策略并有脱敏日志；输入与输出不存在“截断检测、完整放行”。

### R4 · 反依赖计数与豁免正确性

证据：`src/features/chat/useChat.ts:43-49,90-102,131-138`，`src/domain/anti-dependency/antiDependency.ts:8-20,31-53`。

- `useRef(initialValue)` 的实参每次 render 都求值，输入、聚焦、弹层、思考与回复均可读写存储并虚增 `dayCount`。
- 每次 send 重置 `graceShown=false`，单次善终不保证只出现一次。
- `graceDue` 未豁免 `transitionThisSession`，与文件内“层一二三全静默”规则冲突。
- “连续多日高频”只证明连续打开 + 当前日高频，没有历史每日高频数据。
- 本地存储解析缺少运行时字段校验，损坏数据可污染计数。

验收：render 不改变持久化打开次数；只有真实会话打开才计数；善终与跨日提醒满足批准语义；high/批准的 transition 期间全部应静默层级保持一致。

### R5 · 高危期间普通交互让位

证据：`src/features/chat/ChatView.tsx:159-176,210-229`，`src/features/chat/useChat.ts:148-166`。

- 旧 AI 气泡的“继续聊/换个角度”在 riskActive 与 transition 中仍可插入普通陪聊回复。
- 已延迟的 followup 也可能在 high 后落地。
- “联系一个我信任的人”只追加固定文本，没有联系、拨号、复制、分享或跳转副作用；标签与真实能力需一致。

工程可直接关闭普通陪聊绕过；危机按钮应是“查看如何开口”、复制话术还是真实 handoff，以及 high 退出/medium 最低内容，必须由产品与安全专业人员裁决，不得由执行器自行发明临床规则。

原冒烟清单已要求空发送 nudge，因此该可达性修复从 F3 提前并入 R5；其余视觉/可访问性精修仍留 F3。

## 5. 公开生产阻断（体验版后可分阶段，D3 前必须关闭）

### F1 · 云端韧性、滥用与成本

补输入字节/字符限制、可信 OPENID 维度的原子频控/并发/日配额、全局预算熔断、响应体上限、response 生命周期、总 deadline、脱敏指标与告警。客户端 anonymousId 不可信，且当前未构成鉴权或限流边界。

### F2 · 模型与风险协议评测

建立经专业标注的合成/授权评测集，至少覆盖：直接与间接 high、否定/引述/他人/既往、多轮 high 序列、medium 联合内容、提示词注入、诊断/治疗/处方、虚假热线、schema 模糊、风险—内容冲突、依赖与召回、故障与并发。

模型版本、prompt 或温度变更须回归。high 漏判、危机态误退出、异常降 normal、伪造联系方式应作为发布阻断指标；阈值由负责方批准，不由工程自行设定。

### F3 · 生产 UX 与可访问性

已见缺口：

- 空发送按钮 disabled 使 nudge 不可达。
- `scrollIntoView` 后续一直设置相同字符串，后续消息漏滚范围需真机确认。
- 主题只在挂载时计算，跨时段与后台恢复不刷新。
- 失败后原文留在用户气泡，但可编辑草稿不保留。
- 多个核心 View/Text onClick 缺可访问语义，发送图标缺名称，弹层缺 dialog/焦点管理，动态消息缺读屏通知。
- reduced-motion 未停止无限动画，也未关闭原生平滑滚动。
- 部分 placeholder、夜间主按钮和提示文本对比度不足。
- TrustSheet 缺 max-height/内部滚动，小屏、横屏和字体放大需回归。

UI 数值仍须先改 `src/shared/ui/spec.ts` + 测试，再改样式。

### F4 · 隐私、环境与发布治理

- OPENID 不仅用于派生 ID，也用于输入/输出内容安全；披露必须一致。
- “不用于训练”需要第三方条款、账户配置或合同证据；代码只能证明本应用未自行实现训练/服务端画像。
- 当前正文不主动持久化；没有正文 TTL 机制。anonymousId 与本地节律反而长期保存，清除会话不删除它们。
- anonymousId 当前无实际云端用途；公开前决定删除最小化，或基于真实需求重建，不能把它描述成认证边界。
- 发布须记录客户端 commit、云环境、函数版本、配置摘要与契约版本，并建立可执行回滚。
- 根 `verify` 不覆盖云函数 JS、Hook/组件、H5 或真实云端契约；公开前至少把关键测试纳入 CI。
- 完整设备农场、复杂 monorepo、完整观测平台仍可后置，最低发布核验不可省略。

## 6. 有意后置，不作为当前缺陷

不重开 ADR：流式响应、树洞、设置页、多提供方路由、自动历史 feed、opt-in 本地留存、复杂 monorepo、H5 真实云链、大规模设备矩阵均不是当前 R 阶段缺陷。

“生产级危机干预服务后置”不能豁免已经实现的 high 链路出现乱序、异常降级、旧 followup 绕过或反依赖豁免错误。

## 7. Gate R 界面/故障注入验收

R1–R5 完成后，除 `npm run verify` 外至少执行：

1. A normal 延迟、B high 先回、A 后回：B 的风险态不被 A 清除。
2. high/transition 中点击旧普通 followup：不得插入普通陪聊内容。
3. A 失败后发送 B，再点 A 重试：只重试 A，不删除无关错误入口。
4. 慢请求重复点击重试：按批准策略只保留一个有效逻辑结果，无双卡/双回复。
5. 请求或 followup 在途时清除：旧任务不得复活；草稿与元状态按约定清理，可开始新会话。
6. 模拟 401/429/500、非法 JSON、未知 riskLevel：显示明确错误/安全兜底，不显示普通成功回复。
7. 超长输入与检测服务异常：不调用不该调用的模型，不外发/展示未经批准的内容。
8. 连续输入、聚焦、开关 sheet：本地 dayCount 不变；真实第三次打开才出现频次提示。
9. high → transition → normal：反依赖提示按批准协议保持静默。
10. 在真机完成正常回复、高危、内容安全、错误重试、清除与体验版分发；H5 stub 结果不得代替 weapp 云端证据。
