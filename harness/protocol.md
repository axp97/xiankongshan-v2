# 陷空山 V2 执行器协议

## 1. 目的

本文档定义 AI 执行器如何参与陷空山 V2 的交付。

AI 不是架构师。AI 在架构规则、规格和验证标准约束下执行边界明确的任务。
跨会话不偏离依赖：`AGENTS.md` 冷启动 + `harness/memory.md` 的 `## NEXT` + `harness/plan.md`。

## 2. 事实源优先级

当指令冲突时，按以下优先级执行：

1. `harness/rules.md`
2. `docs/architecture.md`
3. `docs/verification.md`
4. `docs/specs/` 下的当前生效规格 + `reference/陷空山UX设计/product-definition.md`（产品契约）
5. 现有实现

**待办与进度**另有唯一事实源（不参与架构冲突裁决，但执行时必须服从）：

- 做什么：`harness/plan.md`
- 现在到哪 / NEXT：`harness/memory.md`

## 3. 执行链路

```text
冷启动（AGENTS.md）
-> 取 plan 中下一「我」任务
-> 实现
-> npm run verify
-> 勾选 plan + 刷新 memory.NEXT
```

## 4. 负责人职责

负责人定义：

1. 架构决策。
2. 业务边界。
3. 数据模型意图。
4. 安全和隐私约束。
5. 验收标准。
6. 非目标。

## 5. 执行器职责

执行器可以：

1. 基于已批准的规格实现代码。
2. 生成规格要求的测试。
3. 在现有架构边界内重构。
4. 将平台 API 转换为基础设施适配器。
5. 报告验证结果。
6. 内部评审无异议、无风险时按 plan 链路继续下一「我」任务（无需等待用户确认）。
7. **全权接管模式（2026-08-08 用户授权）**：能自主验证/推进的事项一律自主完成（含读截图比对契约、跑验证、改诊断性代码、更新文档），只在触达微信/云控制台等物理不可达、或涉及隐私/产品边界决策时才交人工，且交付**最小人工清单**。

执行器不得：

1. 未经批准引入新的架构层。
2. 将业务逻辑移入页面组件。
3. 缺少理由地添加依赖。
4. 将 AI 提供方字段暴露给 UI。
5. 声明尚未实现的安全特性。
6. 超出当前生效规格 / plan 范围扩展。
7. 跳过冷启动或无视 `memory.md` 的 `## NEXT`。
8. 重开 `docs/adr/` 已裁决问题。

## 6. 任务输入（精简）

非平凡任务在动手前在内部对齐以下字段（无需另写文件）：

- 任务（plan 编号，如 B4 / D4）
- 目标 / 非目标
- 验收标准
- 验证命令（默认 `npm run verify`）

## 7. 会话收尾（强制）

每个实现会话结束前必须：

1. `npm run verify` 通过（若改了代码）。
2. 更新 `harness/plan.md` 勾选状态。
3. 更新 `harness/memory.md`：「当前状态」+ `## NEXT`（写明下一「我」任务，以及仍阻塞在「你」的事项）。
4. 若引入新环境坑，追加到 memory「环境与构建的坑」，过期条目删除。

未收尾 = 下一窗口必然偏离。

## 8. 评审模式

当被要求评审时，执行器必须优先关注：

1. 正确性。
2. 架构边界违规。
3. 安全和隐私风险。
4. 类型和数据模型风险。
5. 缺失的验证。
6. 冗余文件或不必要的抽象。
7. 是否偏离 plan / 重开已裁决问题。

摘要优先级低于问题发现。
